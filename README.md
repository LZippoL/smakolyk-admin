# Адмінка Кулінаріуму

Адреса: https://admin.culinorium.com/.

Окремий застосунок React/Vite розміщено у Cloudflare Pages, проєкт `culinorium-admin`. Публічний сайт працює на https://culinorium.com/. Обидва застосунки використовують поточну базу Supabase.

## Вхід

Cloudflare Access спочатку перевіряє email одноразовим кодом. Дозволена адреса: `lubcho224@gmail.com`. Потім потрібно увійти звичайним обліковим записом адміністратора Supabase. Код Cloudflare не замінює пароль Supabase та права редактора.

Кнопка виходу завершує сесію Supabase і відкриває вихід Cloudflare Access. Сесія Access має тривалість 8 годин. Збережені на старій адресі браузерні сесії не переносяться між доменами.

## Публікація

Потрібен Node.js 22 або новіший:

```powershell
npm ci
npx wrangler login
npm run deploy
```

Команда перевіряє TypeScript, збирає застосунок у `output/cloudflare/build`, виконує тести захисту та завантажує збірку у Cloudflare Pages. Git push сам по собі не запускає публікацію: проєкт використовує Direct Upload. Стара команда GitHub Pages видалена.

## Захист

- Access application: `69278890-799e-48d1-8b86-34083646ab6d`, домен `admin.culinorium.com`.
- `public/_worker.js` перевіряє підпис, issuer, audience і строк дії JWT Access перед видачею всіх файлів.
- Усі технічні адреси Pages перенаправляють на захищений піддомен, включно з окремими файлами JS.
- `_routes.json` пропускає всі шляхи через Worker; немає публічних винятків.
- У Cloudflare налаштовано `fail_open=false` для production і preview. Після зміни проєкту цю настройку потрібно зберігати: при відмові Worker файли не мають видаватись без захисту.
- Відповіді мають `private, no-store` і `noindex`. Service worker не кешує адмінку офлайн.
- Доступ до запису в Supabase додатково визначається правами редактора та RLS. Секретні серверні ключі не додаються до Vite-збірки.

Ідентифікатори Access у Worker є публічними параметрами перевірки. Якщо Access application буде створена заново, потрібно оновити audience і перевидати збірку.

## Перевірки

```powershell
npm run build
npm run test:hosting
```

Тести використовують справжні криптографічні підписи: перевіряють дозволений токен, відсутній/підроблений/прострочений токен, неправильний issuer/audience, перенаправлення технічних адрес і доступність файлів збірки. Вони не входять у реальний обліковий запис Supabase й не змінюють рецепти.

Зі старого GitHub Pages прибрано застосунок і його JS/CSS-файли. Там залишено лише перенаправлення на нову адресу та очищення старого service worker. GitHub API відхилив повне вимкнення Pages (HTTP 422); остаточно прибрати й перенаправлення можна в Settings → Pages → Branch: None → Save. Репозиторій вихідного коду зберігається; його видимість є окремим налаштуванням від хостингу.
